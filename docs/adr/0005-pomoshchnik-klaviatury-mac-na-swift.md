# 0005. Раскладка на Mac: отдельный помощник на Swift с CGEventTap

## Контекст
На Windows клавиатуру ведёт поток с хуками, решения принимает общий `Typist`. На Mac этого потока нет, а исправление раскладки нужно и там.

## Решение
Отдельный процесс на Swift (`build/kbd-mac.swift`) ставит CGEventTap и говорит с Node строками JSON. Решения принимает тот же `Typist`, что на Windows: помощник только сообщает нажатия и выполняет команды (напечатать, переключить), без своей логики исправления.

## Почему
- Одно место решений (`Typist`) с одними тестами для обеих систем; расхождение логики между платформами дороже, чем мост.
- CGEventTap нужен нативный; из Node он недоступен без нативного модуля, а модуль привязывает сборку к версиям Electron.
- Отдельный процесс падает без потери приложения и получает своё разрешение «Универсальный доступ».
- Отвергнуто: переписать логику на Swift. Две реализации одних правил исправления.
- Отвергнуто: нативный модуль Node. Пересборка под Electron на каждую версию, а новых зависимостей проект не добавляет.
- Отвергнуто: только `globalShortcut` Electron. Он не видит набираемых клавиш.

## Последствия
- Для Mac нужен ещё один артефакт сборки (скомпилированный Swift) и его упаковка и подпись.
- Протокол между Node и помощником — контракт: менять его надо с обеих сторон одновременно.
- Всё работает только после выдачи «Универсального доступа»; без него возможностей нет (см. 0006).
- Задержка моста добавляется к каждому нажатию, где решение нужно синхронно.
- Windows не проверена на этом Mac: общий `Typist` держит одинаковое поведение, но мост проверен только на Mac.
