# History of decisions (the old CLAUDE.md)

The full CLAUDE.md as it stood on 2026-11-08: every decision with its date, measurements and reasons. Names here are often older (Tyts, OldName, Altype): the app is Tyts now. The short guide is CLAUDE.md.

## What this is

Tyts (Тиць in the Ukrainian and Russian interface and pages; "Your language. Your shortcut."; called OldName until 0.15 (2026-11-03), Altype until 0.11 (2026-10-30), 2Talker until 0.3, tu-talk before that): a Windows tray app (Electron; the `mac` branch also runs on macOS, Apple silicon, `npm run dist:mac`, with the Mac twins named in "Since 2026-11-06") that translates a picked text offline and reads the English aloud; it also translates any text both ways like DeepL, reads text from the screen, and switches and fixes keyboard layouts (in place of EveryLang). A sibling of the Language Tutor in `ikstro/cc-translator` (`E:\Cursor\Plugin\CC-translator`): the card's webview, the natural voice, the system voice and the word dictionary were copied from its `panel/` and adapted; the two repositories do not share code at build time.

Known failures on a Mac, there before 2026-11-06: vitest oldfolder ×3, setup `recommendedModels`, storage (Windows paths), engine `test_move_transcripts`. On a Mac run `env -u ELECTRON_RUN_AS_NODE npm start` with the installed Tyts quit first.

One Tyts at a time, always: `main.ts` takes the single-instance lock on Tyts's own folder before anything else, so a second start (installed, `npm start` or a test run) hands its arguments to the first and quits; an Altype still running (an older install, whose lock is on its own folder) is named in a message and Tyts quits (`oldAppRunning`), as its folders are about to move. A test run (`TYTS_TEST_HOME=<folder>`: its own settings and speech engine folder, `TYTS_TEST_PORT`, 8797 by default, Windows' startup list left alone, nothing moved from the old folders; the `ALTYPE_*` names still read) therefore needs the installed Tyts quit first.

Uninstall (`build/installer.nsh`, `customUnInstall`) asks once whether the data goes too: Yes removes `%APPDATA%\Tyts` (and `Altype`, `2Talker`, `tu-talk`), `%LOCALAPPDATA%\Tyts` (the speech engine; and `Altype`) and `Documents\Tyts` (transcripts; and `Altype`); No keeps everything for a later install; an update (`--updated`) and a silent uninstall never ask or delete; notes in the knowledge base are never touched.

Release: bump `version` in package.json, commit, tag `v<version>`, push the tag. `esbuild.mjs` stamps the main bundle with `TYTS_BUILD` (time, git commit, changed); About, Settings › Version and the tray show the version, and a run from source says "dev" and when it was built (`buildText`), so it is never taken for the last release. `.github/workflows/release.yml` builds and tests on windows-latest with a read-only token (`npm run dist -- --publish never`), then a second job, which runs no npm or PyPI code, drafts the GitHub release with the installer (`gh release create --draft`, `--prerelease` for a tag with a dash); publishing the draft is the owner's step. Actions are pinned by commit, checkout keeps no credentials. Updates (2026-11-08, the owner, replacing "обновление только через GitHub" of 2026-10-30): `src/update.ts` asks `/releases/latest` (drafts and prereleases never count) 5 s after start; a later version brings a question, Update or Later (asked again next start). Update downloads the file with the SHA-256 GitHub states for the asset (`fetchPinned`; no stated hash, no update). Windows runs the installer `/S --updated --force-run` and quits: the data stays, Tyts starts again. The Mac app is ad-hoc signed and cannot replace itself: the dmg lands in Downloads, opens, and Tyts quits so it can be dragged over. No electron-updater, no update files in the release. A run from source never checks. The installer is unsigned.

A shell started from VS Code or Claude Code may carry `ELECTRON_RUN_AS_NODE=1`; Electron then runs as plain Node and `electron.app` is undefined. Run with it unset (`env -u ELECTRON_RUN_AS_NODE …`).

## Architecture

Main process (`src/main.ts`): tray, the card window, the app window, flows. `%APPDATA%\Tyts\`: `settings.json` (`settings.ts`), the person's lists and logs; `words.json` (`words.ts` `WordStore`: the notebook, one entry per dictionary form; `ankiTsv` for Anki's import); `adoptOldFolder` moves them over from `%APPDATA%\Altype` (and `2Talker`, `tu-talk`) once, item by item (`oldfolder.ts ITEMS`: the app's own files, never Electron's caches; `altype.log` becomes `tyts.log`). **Everything downloaded is in one folder**, `%LOCALAPPDATA%\Tyts` (never roamed): `models\<code>\` (Firefox's translator), `voice\` (Kokoro), `dict\`, `translate\`, `speech\`; it was `%LOCALAPPDATA%\Altype` until 0.11 and moves over at start, whole when Tyts has none yet, else part by part (`adoptLocalFolder`); the speech engine's Python remembers its place by absolute paths (`env\pyvenv.cfg` `home`, the junction uv makes for the minor version in `python\`), which `repairSpeech` rewrites (the junction by `unlinkSync`: Electron 45's Node refuses `rmSync` on a junction, which left 0.15.0's moves on OldName's folder; `healSpeech` points a junction that leads nowhere at the folder beside it at every start), so it runs as it was with no new install (its packages' hard links into uv's cache move with it); uv 0.13's `env\Scripts\python.exe`, the one Tyts runs, keeps its Python's absolute path inside the file (`UV_PYTHON_PATH`), so a launcher that names an old name's folder (`SpeechPack.moved`) is made again at the engine's start by `uv venv --allow-existing` (`relocate`: a second, packages kept, nothing downloaded; once a run; should uv fail, the environment is synced again from the cache, the models kept; 2026-11-03: 0.15.0 on the owner's laptop never started the engine, "uv trampoline failed to spawn Python child process", and dictation said "The speech engine is starting" at every press; it now says when the engine gave up, `dict.engineDown`, a click opening Report a problem); the first three lived in `%APPDATA%` until 0.10.1 and move over once at start (`oldfolder.ts moveDownloads`); a part that cannot move is used where it is (`partDir`, `localPart`, `downloads`; the engine is told its folder, `TYTS_SPEECH_DIR`); a program run from inside the old folder keeps its files in use (the speech engine's python.exe and uv.exe, llama-server.exe, left by Altype or a run from source), so while the old folder holds a part Tyts's has not (`hasToMove`), those programs are stopped first (`freeFolder`: Windows' list through PowerShell `-EncodedCommand`, CIM `Win32_Process.ExecutablePath`, `holdersIn` picks those under the folder, never Tyts or Altype.exe, which `oldAppRunning` waits for), and `tyts.log` says what was stopped and what stayed and why (`leftIn`, `whyLeft`: "left in …\Altype: speech (a file in it is in use by python.exe)"; a part Tyts has its own copy of stays, unused). The old names' updater downloads (`%LOCALAPPDATA%\altype-updater`) go. Closing the card (`hideCard`: Esc, ✕, a click elsewhere) also sends `stop` to the card, which plays the natural voice's audio itself. Esc and ✕ (`closeCard`, 2026-10-30) first give the keyboard back to the window in front when the card opened (`cameFrom`; a Translate card from a selection, its `pasteTarget` window and field, as Paste does), as a hidden card leaves Windows to bring up a window of its choosing; a click elsewhere only hides it.

- **Selected text**: `winclip.ts` registers the card window as a clipboard listener (user32 through koffi; `WM_CLIPBOARDUPDATE` via `hookWindowMessage`). `clipboard.ts` `DoubleCopy`: two changes 40–650 ms apart with Ctrl held = a request (`doubleCopy` setting); changes closer than 40 ms are one copy announced in several formats. Copies made inside the focused card are ignored. The selection shortcut (`selectKey`, none by default) waits until its keys are let go, presses Ctrl+C in the program in front (`pressCopy`, `keybd_event`) and takes the next clipboard change within 2 s (`COPY_WAIT_MS`, `copyWanted`; 600 ms until 0.10.1, too short for a busy VS Code, whose late copy was thrown away as "Nothing was copied"; `tyts.log` says "copy: came in N ms from <exe>" or "copy: nothing in 2000 ms"; the fix key's `convertOver` waits as long). `registerShortcuts()` registers it and `snipKey`; either may be empty.
- **Screenshot**: the snip shortcut (`snipKey`, default Ctrl+Alt+S) opens `ms-screenclip:` (Windows' snipping overlay); the next picture on the clipboard within two minutes is the snip (`clipboard.read()`, `image/png`; Electron 45's clipboard API is async). `ocr.ts` runs `Windows.Media.Ocr` through Windows PowerShell (`-EncodedCommand`, never `-ExecutionPolicy`): every installed engine of the person's languages reads the snip (their own first, English last; small text, lines under 20 px, scaled up twice first: three times read worse), and `ocrpick.ts` `pickLines` takes each line from the reading that reads it best (`lineScore`: words in the person's lists count for it; Cyrillic or Greek look-alikes between Latin words, a bracket by a letter, mixed scripts against it), then its doubtful words from another reading where the line reads better (`mergeLine`). One engine is not enough (2026-10-29): the Russian one wrote English "can", "a", "gpu" as "сап", "а", "дри", which the direction rule then sent into English; `ocrtext.ts` joins lines into paragraphs by their boxes. Two purposes (`Purpose`), each from the selection or the screen: **listen** (the card above: `doubleCopy`, `selectKey`, `snipKey`) and **translate**, the translator (`translateKey` with `useSelection('translate')`, `textKey` with `snip('translate')` → `readScreenText`): the same card in kind `translate` or `text`, the text as it is (editable, its English words clickable), Copy, From ⇄ To over the 32 languages, translated at once (`translateWindow`, `translateTextCard`). `translate.ts` `languageOf` guesses the source (a script of one language; letters of one language: қ… kk, і/ї/є/ґ uk, ђ… sr, ы/э/ё ru, پ… fa; else the language with most of its 200 common words in the text, `media/lang-words.json`; a short text: English by `media/layout/en.txt`), the vote and the English rule only among the languages the person uses (`pool`: `settings.ts myLanguages`: their own, English and `languages`, chosen in Settings; a script none of them uses falls back to all 32), `targetFor` the target (the person's own, English from it), `translatePlain` translates through English when neither side is. No Translate button: an edit is translated again after a 700 ms pause (the last translation shown faded meanwhile), a language picked at once. Swap (framed, after the languages) swaps them and, a translation in, makes it the text (DeepL's way). Paste (blue; Enter on the window or in the field, Shift+Enter a new line; a translation still coming is pasted once in; only for a selection, `canPaste`): `pasteTranslation` brings back the window the text was selected in (`focusWindow`, `SetForegroundWindow` while the card is in front), hides the card and pastes over the selection through the clipboard. Nothing of Tyts's is left on the clipboard (2026-10-29): every borrowing (the selection keys, Paste, Translate in place, the fix key over a selection, a dictated phrase, Chrome's address, the snip) goes through `clipguard.ts` `ClipboardGuard` over `winclipboard.ts` (user32 through koffi, the card's window owning the writes): `hold` keeps every format there (copied files and Office's formats too; GDI handles and private formats are not kept), one snapshot for a run of actions close together (the fix key pressed twice); Tyts's writes and its putting back carry `ExcludeClipboardContentFromMonitorProcessing`, `CanIncludeInClipboardHistory` = 0 and `CanUploadToCloudClipboard` = 0, so Win+V and the cloud clipboard never see them; a text to paste is only promised (`writeText(…, paste)`, Windows' delayed rendering: `SetClipboardData` with no data, handed over in `WM_RENDERFORMAT` through the card window's hook, `watchRendering`), and `ClipboardGuard.read` decides who gets it: before Ctrl+V (`pasted`) nobody is pasting, so a program asking then is one watching the clipboard against the history marks and gets nothing (2026-10-30: Viber reads every change within a millisecond, which hid the paste's own read), after it the paste's program does, and that read is the signal; `release` puts it back `AFTER_READ_MS` (150) after it, `READ_WAIT_MS` (2.5 s) at most when no read is seen (a fixed 500 ms before let a slow program paste the old content), only while the clipboard's sequence number is still one of Tyts's (`write`, `claim` for a copy Tyts pressed) — a copy the person made meanwhile stays — and writes nothing when nothing changed; another program holding the clipboard is waited for; quitting puts back at once (`flush`, before the windows close). The listener skips Tyts's own changes by their number. A selection key that finds nothing copied waits `LATE_COPY_MS` for a late copy (Ctrl up) to take back too; the snip puts back what was there once the picture is read, and a copy without a picture ends the wait for it (Ctrl+C twice works again at once). Windows' own snipping tool still puts its picture in Win+V. Ctrl+C twice is the person's own copy.
- **Translation**: `translate.ts` `pairText` splits lines into sentences (`sentences.ts`) and decides each sentence's direction by script (`directionOf`): the person's script → into English (English shown, original behind the tap), Latin → into their language. Same-script natives (German…) are treated as English source for now. `splitText` + `translateLines`: when no sentence goes into English (`englishReady`), `main.ts` `translateInto` shows the English at once (`done` with the translation `translating`/`downloading`) and the card starts reading while the translation comes. `render.ts` writes two halves as plain paragraphs, one per line (no markdown: a picked text is not markdown; `sentences.ts` `unwrapLines` first joins lines broken mid-sentence: a line ending in a letter, digit, comma or hyphen followed by one starting in lower case without a list marker; a list item goes on so too): `englishHtml` (`span.s[data-i]`) and `translationHtml` (`span.t[data-i]`).
- **Translator** (`engine.ts`, interface `translator.ts`): Firefox Translations (Bergamot, WebAssembly, `vendor/bergamot`, shipped). Models per pair from Mozilla's attachment CDN, pinned with size and SHA-256 in `src/mt-manifest.json`, stored as `<sha256 head>-<name>`. `scripts/build-mt.mjs` picks, per direction, the newest complete version whose filter expression passes for Windows release (en→ru 2.0; the nightly 2.1 invents words). The engine runs in a worker thread (`mt-worker.ts`, loader via `vm.compileFunction`, Firefox's decoder config), ended after 5 idle minutes.
- **Translation levels** (2026-10-29; one model for translation and checking since 2026-10-30, 0.10.2: `settings.translationLevel`: `fast` | `accurate` | `most`, `LEVEL_NAMES`, and `settings.model`: `accurate` | `most`, the one local model, which Check my English always uses; `normalize`'s `levelAndModel` keeps them in step, the model winning, so a model picked on the Check page moves a level that was the other model; `main.ts activeTranslator()` is the level's translator, and `translationJob(codes)` what every flow takes: `translateInto`, `translateTextCard`, `translateInPlace`, dictation's `toEnglish`): Fast is Firefox's models above; `unzip` by Windows' tar; `engine.ts` and `speechpack.ts` download through it too) into `%LOCALAPPDATA%\Tyts\translate` (`engine\<vulkan|cuda>-<sha256 head>\`, `models\<sha256 head>-<file>`; `llmPaths`; thinking off, `temperature` 0, no prompt cache), four at a time; the whole paragraph given as context read a little better but cost 40 % more and once repeated a sentence, so it is not sent. `LlmFiles.remove(model)` stops the server first (Windows keeps a file in use), and a build no model left needs goes too. `llama.ts LlamaServer`: one model at a time on a free port of 127.0.0.1 (`-c 8192 -np 4 --kv-unified --no-webui`; on Vulkan llama.cpp's own `--fit` puts as many layers on the card as it holds, on CUDA `-ngl all`, NVIDIA's driver lending the card the computer's memory), started by the first request (or ahead of it, `warm`: a selection, snip or empty-card key that will need the model starts it at the press, `main.ts warmModel`, so its ~3 s load runs while the text is copied or typed), stopped after 3 idle minutes (10 until 2026-10-31) and with Tyts, and a resting one (15 s or more without a request, `restingFor`) when a program goes full screen (`stopForFullScreen`, `winkbd.fullScreenNow` every 5 s, `watchModel`; "model: stopped for a program on the full screen" in tyts.log), its output in `%APPDATA%\Tyts\translate.log`; a model that cannot start on the card is started on the processor (`--device none`) until Tyts restarts.
