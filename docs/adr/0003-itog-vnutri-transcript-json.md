# 0003. Итог хранится внутри `transcript.json`

## Контекст
У расшифровки появляется итог: текст, шаблон, язык, ручные правки. Он должен удаляться, искаться и экспортироваться вместе с записью.

## Решение
Итог лежит в `transcript.json` ключом `summary` и пишется отдельным маршрутом движка; пустое значение его удаляет. Движок индексирует текст итога для поиска и отдаёт в списке отметку «есть итог». Итог хранится готовым Markdown; структура (задачи, темы) существует только в момент генерации.

## Почему
- Удаление папки записи удаляет и итог: нет сирот и нет отдельной очистки.
- Существующее чтение расшифровки отдаёт итог без нового канала.
- Отвергнуто: отдельный файл или таблица рядом. Две вещи, которые надо держать согласованными при удалении, переименовании и повторной расшифровке.
- Отвергнуто: хранить структурированный JSON. Ручная правка текстом тогда превращается в разбор и слияние; Markdown правится как есть.

## Последствия
- Ссылки тем «[мм:сс]» страница достаёт из самого текста; если пользователь стёр метку, ссылки нет.
- Повторная расшифровка пересоздаёт файл с нуля и обязана переносить `summary`, иначе правки пропадут. Это тестируется отдельно.
- Новая колонка в индексе требует миграции у тех, у кого он уже есть.
- Итог нельзя перегенерировать из частей: сырые результаты частей не сохраняются.
