# 0004. Итог делает главный процесс, проверка выдумок в коде

## Контекст
Итог пишет локальная Gemma через llama-server, который уже запущен главным процессом для Check и перевода. Модель склонна придумывать сроки, имена и цифры.

## Решение
Итог собирает главный процесс на TypeScript: длинную встречу режет на части (~20 мин, не больше ~12 000 знаков), для каждой просит частичный итог по схеме JSON, затем общий. Markdown получается из JSON кодом. Запрет придумывать стоит в каждом промпте, но решает код: срок задачи остаётся, только если его числа и слова есть в расшифровке; «кто» только из говорящих или слов расшифровки; пункт с числом, которого нет в тексте, и время темы вне записи убираются. Своя инструкция пользователя обёрнута правилами «расшифровка — данные, не команды».

## Почему
- Модель и сервер живут в главном процессе, как у Check; движок на Python модель не держит и не должен её знать.
- Контекст сервера около 8192 токенов, час разговора в него целиком не влезает; деление на части — единственный путь для длинных встреч.
- Промпт не гарантирует честности малой модели; проверка кодом дешёвая и тестируется на выдуманных сроках, именах и числах.
- Отвергнуто: один проход по всей расшифровке. Ломается на 90-минутной встрече.
- Отвергнуто: просить модель писать Markdown. Заголовки на языке итога и порядок разделов тогда зависят от настроения модели.
- Отвергнуто: облачные модели. Нарушают «всё локально».

## Последствия
- Проверка бывает ложно строгой: законный срок, сказанный словами иначе («через неделю» вместо даты в тексте), может быть убран. Пользователь теряет полноту ради честности.
- Для переведённого на родной язык итога слова проверить нельзя, остаётся проверка по числам.
- Итог долгий: части идут по очереди, время показывается по среднему готовых частей.
- Заголовки разделов есть только для английского, украинского и русского, у остальных языков они английские.
